## 诊断接口的权限范围

`/api/upstream-test` 仍需要有效管理员会话和严格同源 POST；已保存站点诊断也需要管理员认证。它们不会复制入站 Cookie、Bearer 或站点自定义凭据，即时测试也不返回原始上游响应体。HTTP 客户端正常验证证书，拒绝跨协议、主机或端口的跳转，并限制超时与响应读取。

访问正常 loopback、RFC1918 和 IPv6 ULA 回源属于管理员权限。特殊目标策略用于防止诊断误触云元数据等服务，不意味着所有内部服务都安全，或已限制拥有管理员权限的人配置业务反代。管理会话、服务器网络和容器出口仍应按实际部署保护。

任意 URL 测试每个 Controller 应用实例最多同时执行 4 个请求，允许 24 个请求的突发额度、每秒恢复 1 个额度；超过限制返回 `429` 与 `Retry-After`。普通线路逐个测试、站点列表延迟、节点调度和自动故障切换保持各自功能。审计日志只记录目标主机及结果，不记录 URL 查询、请求凭据或上游响应体。

## 审阅与发布

高风险结果应逐项处理：有效问题修代码；有明确安全边界的结果记录规则、指纹、边界文件与验证依据。不要仅加 `nosec`、按整条规则屏蔽，或把所有历史告警一次性关闭。

审阅记录必须随源码变化复核。若放宽 CSP、扩大可用响应类型、改变 capability 授权、放宽转发头信任、变更健康检查目标，或把临时身份键用于持久密码验证，不能继续沿用本次结论。

门禁只接受精确结果的原始 CodeQL 指纹，记录的保护实现与测试必须保持匹配，有效期最长 90 天。未审阅的严重或高危结果会阻止检查通过；中低风险仍保留在报告中。正式发布还需确认当前标签提交的主分支 CodeQL 已成功执行，并重新核对该提交的扫描结果。具体记录格式、单维护者更新方式和信任前提见[门禁政策](../.github/codeql-review-policy.md)。本文件中的复核不会自动关闭 GitHub 告警。

## 2026-11-21 实现变更复核

本轮修复重新核对了已有审阅记录涉及的实现。转发头的默认信任范围保持不变，新增的外部反代部署状态只用于判断 Host 入口是否可用；真实入口仍检查代理连接来源，诊断的目标地址、DNS、重定向和凭据限制继续生效。动态媒体传输遇到读取或写出错误时，在已发送响应头后终止响应，让播放器识别未完成的分片；响应的 CSP 沙箱、类型限制和会话 Cookie 隔离保持有效。

诊断安全、动态资源边界和真实 HTTP 分片回归分别验证这些约束，新增 `panel_ingress_configuration_test.go` 与 `proxy_response_reliability_test.go` 随审阅记录绑定。原有规则与 CodeQL 指纹保持不变，仅更新已复核实现、测试和本文的规范化哈希。这次源码复核不能代替新提交的 CodeQL 分析；后续正式发布仍需要该提交自己的成功扫描。

实际播放后的追加优化将动态连接池限制在单个运行站点，并按规范化目标、已验证 IP 集合、接口快照和策略代次隔离。每个请求继续检查目标与 DNS/IP，证书验证、禁环境代理、凭据和响应隔离继续生效；取消或未完整读取的连接不会复用。新增请求计时只使用程序自己的观察回调，动态上下文仍不接受外部 `Got1xxResponse`。已验证能力路由的后台路径分类仅在 capability 的密封、时效、站点与注册检查通过后生效。

`dynamic_transport_pool_test.go`、`request_diagnostics_test.go` 与独立真实 HTTP 101 回归检查了策略更新、DNS 重绑定、站点隔离、取消、响应头和双向传输。缓存诊断只记录固定原因和数值，不记录凭据、Cookie 或查询字符串。以上追加复核没有扩大原告警的例外范围；原规则、路径和精确指纹继续保持绑定。

逐次回源记录继续由程序自己的 transport 回调采集。配置回源保留 ReverseProxy 的信息响应处理，动态回源不继承调用者的 trace 或凭据；HTTP 101 的双向正文保持可读写。记录的目标只包含规范化的 HTTP(S) 协议、主机和端口，不包含路径、查询或 URL 用户信息。每条请求最多保留前七次与最后一次实际回源，并限制序列化大小；最后一次失败不会沿用前一次重定向的响应和连接信息。写入、展示及节点输入验证覆盖这些新增字段。`request_upstream_attempts_test.go` 使用真实重定向、动态回源、连接失败、连接池复用、103/101 和独立读写开关验证这些边界。

停止播放反馈只作用于已观察到成功播放的会话。请求的站点、媒体、会话、客户端凭据证明与已认证节点来源需要匹配；同批处理以最新成功播放的证明为准。客户端完整提交停止请求后可以显示未确认意图，只有实际源站返回 204 才记录成功停止和最终进度；拒绝、取消、乱序进度及重复上报分别处理。该功能不脱离客户端重放请求，也不新增明文播放令牌，观看历史响应不暴露内部会话证明。普通请求日志关闭时，节点的必要观看记录仍通过原有关键事件及 ACK 通路传送。

本轮性能优化将动态清单的同主机 DNS 结果限制在单次重写会话内复用。每个 URL 继续核对当前策略代次、接口自目标和完整地址集合，后续实际能力资源请求重新解析并固定允许的数字 IP。多地址拨号在原总期限内给后续已验证地址保留时间，不使用系统二次解析或放宽业务 TLS 校验。动态媒体的 MIME 限制、凭据过滤和 CSP 沙箱继续生效。

普通资源冷缓存改为有大小上限的临时文件流式填充；既有 Cookie、private/no-store、Vary、鉴权命名空间限制继续决定缓存资格。只有完整 EOF、长度与当前代次检查成功才发布，取消、截断、超限和磁盘错误不发布半对象。面板静态缓存仅适用于嵌入的 JS/CSS/SVG 精确内容指纹，不包含 API、账户、诊断或媒体响应；HTML 和旧资源 URL 继续禁止长期缓存。性能回归测试与原有安全边界测试共同覆盖这些变化，本次源码复核不代替新提交的 CodeQL 分析。
