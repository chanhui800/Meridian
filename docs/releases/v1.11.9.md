# Meridian v1.11.9

v1.11.9 新增独立的通用 HTTP(S) 反代模式，一个站点入口可按客户端请求路径连接多个媒体服务器，并完善多来源观看记录、媒体后端改写与节点接管行为。已有固定回源站点继续使用原模式。

## 通用反代

- 新增站点默认固定回源，开启“通用反代”开关后无需配置主回源和备用线路；支持域名前缀及独立端口入口。
- 客户端服务器地址填写 Meridian 入口，路径可直接填写 `http://192.168.1.10:8096/emby` 等完整回源 URL，也支持 `/_proxy/v1/http/192.168.1.10:8096/emby` 格式。
- 每个请求独立解析协议、主机、端口和路径；支持 HTTP、HTTPS、域名、IPv4、IPv6，以及承载主控或节点能够连接的本机、局域网和公网目标。
- 保留请求日志、实际后端地址、收发流量、UA 策略、额度和限速。通用模式不启用固定备用线路、静态资源缓存、保号周期、站点固定请求头或主视频流直连，也不提供 CONNECT 隧道。
- README 将通用模式单独列出入口、客户端用法与能力对比；新增[通用反代完整指南](../generic-proxy.md)。

## 播放与媒体后端

- 改写 PlaybackInfo、HLS/DASH 和 HTTP 重定向中的 HTTP(S) 地址，支持相对路径、内网资源、字幕、分片以及独立媒体后端。
- 兼容媒体客户端将已改写的通用路由追加到原 Emby 基路径的请求，避免播放地址嵌套后被错误发送到 API 前端。
- 保留 Emby 挂载路径下的自定义播放地址，同时正确处理标准媒体资源路径。
- Range、HEAD、查询参数、WebSocket 与实际字节计量沿用反代语义；重定向和最终媒体响应在请求日志中显示实际后端。
- 通用模式的重定向与上游 Cookie 路径按目标路由处理，媒体继续通过 Meridian 入口访问。
- 无法规范化的上游跳转地址不会作为原始 Location 返回客户端；合法的相对地址与 HTTP(S) 跳转继续改写为通用路由。
- gzip 头初始化与正文读取共用超时保护，上游停止发送压缩头时会释放解析额度；读取失败与提前退出继续保留原正文重放语义。

## 多来源观看记录

- 通用站点可以独立开启观看历史，普通编辑保留已有设置。
- 按服务器及 API 挂载路径隔离媒体 ID、播放会话、剧集归属与元数据，避免多台服务器或多个挂载返回相同 ID 时混合记录。
- 观看记录、正在观看卡片与详情显示服务器的协议、主机和端口，不显示挂载路径、查询参数或凭据；固定回源记录不增加地址栏。
- 已有记录只在保留的成功 API 日志能精确确认来源时补齐地址，其他记录等待该来源后续播放更新。
- 停止意图与源站停止确认继续分开处理，多来源身份同时用于会话与停止状态匹配。

## 节点调度与主控入口

- 通用域名站点可跟随全局调度或固定节点。旧 Agent 会显示等待升级；已经由旧节点承载的固定站点，需先升级生效 Agent 再切换通用模式。
- 本机和内网连接由实际承载站点的 Controller 或 Agent 发起，`localhost` 随承载位置确定。
- 节点首次正式接管后，Controller 对该站点的新请求返回 HTTP 421；已开始的视频和 WebSocket 连接继续运行。
- 后续节点切换等待或失败时保持主控入口关闭，关闭调度并完成 DNS 与节点清理后才恢复。面板管理接口与其他站点独立运行。
- 主控入口的节点归属与生效配置一致保存和恢复，Controller 重启后继续遵守已接管状态。

## 升级与回退

正式文件和 `SHA256SUMS` 见 [v1.11.9 Release](https://github.com/chanhui800/Meridian/releases/tag/v1.11.9)，固定镜像为 `ghcr.io/chanhui800/meridian:v1.11.9`。更新 Controller 后，已注册 Agent 会后台下载并校验匹配版本，保留身份与状态，普通升级无需重新注册。

本版本将数据库自动迁移到 schema 58，加入回源模式与通用观看来源信息。升级前保存一致的数据库备份；回退旧版本需要匹配的数据库备份或受控迁移，不能直接用旧二进制读取新 schema。

保存固定站点为通用模式会移除固定回源线路、预设播放地址、缓存、保号周期和固定请求头设置，切回固定模式时需重新填写。已有固定站点不会因升级自动切换模式。

## 验证

相关回归覆盖两种通用路径格式、本机和内网目标、PlaybackInfo 与媒体重定向、Emby 基路径、Range 及实际后端日志、多来源观看隔离与来源地址迁移、Agent 配置兼容，以及节点接管后的主控 421、存量连接与关闭调度清理。

正式发布流程对精确主分支提交执行 CI、CodeQL 和发布检查，生成二进制、安装器与 SHA-256 校验文件，并发布 amd64/arm64 镜像。
