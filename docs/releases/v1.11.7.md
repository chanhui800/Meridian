# Meridian v1.11.7

v1.11.7 改善播放反代、缓存、请求日志与观看记录，减少重复 DNS、数据库查询和磁盘写入，并修复新节点 IPv4/IPv6 字段不能自动填入的问题。

## 播放与反代

- 修复备用线路选择、等价播放地址回退、重定向与 Cookie 基路径处理，以及配置改变后的缓存隔离。
- 统一处理普通回源、动态资源和 WebSocket 的读写错误；响应已开始后遇到截断会终止传输，避免播放器把未完成分片当作成功内容。
- 保持 Range、HEAD、客户端取消及实际收发字节的语义，区分客户端取消、源站截断和回源失败。
- 按站点、目标、已验证 IP、接口状态和策略代次复用动态连接，使用有界复制缓冲池。每次实际资源请求仍检查 DNS/IP，继续验证业务 TLS 并隔离凭据。
- 缓存冷图片时边传输边填充独立的临时文件；完整 EOF、长度与当前配置代次全部符合后才发布。取消、截断、超限或磁盘错误不会留下半个缓存对象，`private`、`no-store`、Cookie 与身份隔离规则继续生效。

## 日志、观看记录与页面

- 请求详情显示逐次回源的连接、响应头和首字节耗时，区分重定向、备用尝试及最终连接；补充实际响应状态、传输结束原因和缓存查找/写入结果。
- Controller 与 Agent 使用一致的日志策略。关闭普通请求日志时，必要的观看记录仍通过关键事件和 ACK 通路传送。
- 修复突发新日志遗漏、异步弹窗结果写入已关闭页面等问题。实时日志刷新保留当前阅读位置。
- 观看历史区分停止意图与源站确认；匹配已验证的成功播放会话，只有源站实际返回 204 才确认成功停止及最终进度，并处理取消、拒绝、乱序和重复上报。
- 点击站点行展开或收起详情，拖拽手柄在鼠标悬浮时显示。整理添加站点弹窗与全局诊断结果布局，保留站点延迟和全部测速功能。

## 性能优化

- **代理与缓存：** HLS/DASH 同主机 DNS 结果仅在一次清单重写内复用；实际资源请求重新校验。多个已验证地址共享原有总拨号期限，给后续地址保留尝试时间。低于预算的缓存检查使用常数时间路径，冷缓存流式传输减少首段等待。
- **节点后台：** 保留每轮健康探测，稳定 DNS 的漂移检查按五分钟维护，省去内容未改变的 DNS 写入。事件预算序列化按线性方式处理；有界加密追加日志批量写普通事件，关键事件接收和 ACK 仍可靠持久化，并对磁盘失败退避。
- **数据库：** 新增 TMDB 关联复合索引及未处理节点事件覆盖索引；观看历史先定位窄字段页，再补齐元数据；流量汇总按数据库变化精确失效，仍包含实时待写计量。
- **面板：** 嵌入的 JS/CSS/SVG 使用内容指纹、预压缩 gzip、表示专属 ETag 和 304。只有精确指纹资源允许长期缓存，HTML 与旧资源地址保持 `no-store`。仪表盘趋势合并保存，离页刷新，兼容旧记录并限制存储大小与配额失败重试。

## 节点地址与安装

- 注册时在同一事务内把可信公网地址填入对应的空 IPv4/IPv6 字段；已有节点通过认证的完整上报自动修复空字段。
- 真实公网地址提示优先，兼容 NAT 节点没有公网网卡地址的情况；保留已填写的手工地址，没有可确认的公网 IPv6 时保持为空。
- 分开判断转发头信任与外部反代是否已部署。外部代理承载 Host 入口时，需设置 `PANEL_EXTERNAL_PROXY_ENABLED=true` 并限制可信代理来源；默认信任私网不会自动声明已部署反代。
- 安装器管理的 Nginx 为备份恢复和图标包导入/刷新设置相应请求大小限制，更新时保留可识别配置的 Certbot 证书与 HTTPS 跳转。配置检查或重载失败会恢复原配置。

## 升级与回退

正式文件和 `SHA256SUMS` 见 [v1.11.7 Release](https://github.com/chanhui800/Meridian/releases/tag/v1.11.7)，固定镜像为 `ghcr.io/chanhui800/meridian:v1.11.7`。升级 Controller 后，已注册 Agent 会后台下载并校验匹配的正式二进制，保留节点令牌及状态，无需重新注册。

v1.11.6 的数据库 schema 53 会自动升级到 56。保留升级前的一致数据库备份；降回旧正式版需要匹配的数据库或受控迁移，不能仅替换旧二进制。已运行 schema 56 的预发布版切换本正式版不需要新的 schema 迁移。

Agent 正常停止和自动更新会等待队列写入完成并导出兼容旧版的格式，导出失败会阻止程序替换。降级应先正常停止 Agent；积压超过旧格式容量时先恢复上报并等待队列消化。

使用私网网段的已有外部反代、且旧配置没有显式部署状态时，应设置 `PANEL_EXTERNAL_PROXY_ENABLED=true`。单地址可信来源的旧配置保留兼容判定；入口的实际连接来源仍需可信。

## 验证

本次实现经过 Windows 与隔离 Linux 全量 Go 测试、相关 race、Windows/Linux/Darwin vet、342 项前端回归及真实浏览器验证。AWS 预发布验证覆盖数据库完整性、配置与身份保留、节点版本/队列/地址，以及 22 项公开资源的内容校验、gzip、长期缓存与 304。

正式发布流程另对精确主分支提交执行 CI、CodeQL 和发布检查，生成七种二进制、安装器及 SHA-256 校验文件，并发布 amd64/arm64 镜像。CodeQL 按具体指纹和保护实现的摘要复核，不放宽规则级例外。
