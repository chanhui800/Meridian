# v1.11.12

此版本改进 Agent 的公网地址发现、DNS 与监听地址族、安装入口和 Cloudflare 记录恢复，修正仪表盘请求与站点流量的展示口径，并阻止通用反代的跨回源播放地址继承原请求凭据。

## Agent

### 安装与升级

- 添加节点或“重新生成脚本”后，面板只展示并复制一条一键安装命令。命令包含有效期为 24 小时的一次性注册令牌，在目标 Linux amd64/arm64 节点以 root 权限执行。
- 已注册 Agent 继续跟随 Controller 自动更新：通过认证清单取得固定版本下载信息，后台校验平台与 SHA-256，确认配置仍有效后原子替换并由服务管理器重启。普通升级保留节点身份，无需重新注册。
- 本地状态丢失、长期令牌失效或更换 Controller 时，再使用面板生成的 `--reenroll` 命令。生成命令本身不会立即撤销当前 Agent，替换注册成功时才切换凭据；同一 Controller、同一节点记录上的重新注册保留 GUID、流量与调度关联。

### 公网发现与地址展示

- 注册、HTTP 完整报告和 WebSocket 报告可使用 Controller 观察到的可信公网来源补全节点地址。Agent 某一族没有本机公网地址时，会通过该族单独连接认证接口，补全 NAT 后的公网出口，即使日常控制连接走另一族也可尝试发现。
- 回环、私网、链路本地和 `100.64.0.0/10` CGNAT 地址不作为公网候选。手工确认的地址会保留，自动来源可随 Controller 新的来源观察更新；网卡能力摘要只上报名称与地址族。
- 前置代理必须来自已配置的可信来源，并提供规范化的单值 `X-Real-IP`。不明确的转发信息不会把代理地址误写为节点地址。
- 节点主行按 DNS 发布族显示地址：“仅 IPv6”显示 IPv6，其余模式以 IPv4 为主。自动模式缺少 IPv4 时，主行可能显示等待，可在展开详情查看已发现的 IPv6 和实际 DNS 状态。

公网出口发现仍依赖 Controller 在相应地址族上可访问，也不能代替 NAT/CGNAT 的公网端口映射、防火墙和入站路由。入口不可达时，Controller 保持等待，不会据此直接发布 DNS。

### DNS 与监听地址族

- “仅 IPv4”绑定 IPv4，“仅 IPv6”绑定 IPv6，另一族的同号端口保持可用。可在地址尚未上报时先保存策略，DNS 等待对应公网地址和健康检查；收到站点配置后只监听指定族。
- 自动模式按已知公网地址决定监听：只有一族时只绑定该族，两族都有地址时分别建立两族监听；两族都没有地址时，对新旧 Agent 均下发空路由，暂不占用业务端口。
- 双栈监听的一族建立失败时，本次配置应用失败并尝试恢复旧配置；不会留下只生效一半的双栈监听。修改发布策略或发现新的地址族会使配置重新下发。
- 新监听字段仅发给支持它们的 v1.11.12 及以后 Agent，旧版本的字段与配置哈希保持兼容。单栈端口隔离需等待 Agent 自动更新完成，其他服务的双栈通配监听仍可能造成冲突。

### Cloudflare 与站点调度

- 发布 DNS 前分别验证每个拟发布地址的 HTTPS/SNI 与 Agent 身份。双栈中的一族失败时，不能借用另一族的健康结果，也不会开始本轮 DNS 维护。
- A/AAAA 切换会确认或创建目标族记录，并跟踪旧族清理，支持在删除暂时失败后继续恢复。
- Cloudflare 重复地址错误、并发创建或创建响应丢失时，只恢复带有本站点 Meridian 所有权标记的唯一记录，并在接管前按 ID 重新验证。无标记、多个候选或已变化的记录继续显示冲突，保留给管理员处理。
- 已存在记录的恢复保留变更前内容，本地调度提交失败时可补偿恢复，避免把其他轮次创建的记录误当作本轮新记录删除。

## 请求与流量

- 仪表盘主指标改为“本月请求”，按全局调度时区的自然月汇总 Controller 与 Agent 的持久记录，并加上尚未持久化的实时请求增量；Agent 会话或站点计数周期切换后重新计算增量。
- 主指标不随图表所选日期范围或站点改变。图表继续显示其选定区间和站点的数据；自定义流量重置日也不会改变请求的自然月口径。
- 站点管理主值与额度进度改用当前计费周期流量，累计流量保留在展开详情中。流量周期仍遵循全局计费方式、调度时区与重置日。
- 请求汇总使用独立缓存，纯请求入账或时间范围内的记录变化会失效刷新，不会把自然月请求窗口和流量额度窗口混用。

## 播放凭据

修复通用反代 PlaybackInfo、HLS 和 DASH 中跨协议、主机或实际端口的播放引用：改写路由不再向新的回源目标继承客户端认证头与 Cookie，嵌套引用继续保留这一限制。同源相对地址仍保留所需凭据，目标 URL 自身的签名查询、DASH 模板与 Range/206 播放继续支持。

## 数据库与回退

从 v1.11.11 升级时，数据库由 schema 60 自动迁移到 61。`control_nodes` 新增 `reported_interfaces` 和 `listen_interface` 两个有默认值的字段，用于网卡能力摘要及兼容；监听族由 DNS 策略计算，面板不提供网卡选择。现有节点、地址、流量与调度数据保留，备份文件格式不变。

升级前备份数据库及需要的 TLS 状态。schema 61 数据库与由其生成的备份不能直接交给 v1.11.11 或更早程序。回退到 v1.11.11 时，先停止服务，再恢复升级前的 schema 60 数据库及配套配置/TLS 状态；仅替换旧版程序不会降级数据库。回退到其他版本需恢复该版本支持的备份，例如 v1.11.9 使用 schema 58。

建议先升级 Controller，再等待各 Agent 自动更新并确认配置已应用、监听族和 DNS 状态。无需为普通升级刷新注册令牌。Agent 降级前仍需正常停止并完成事件队列的兼容导出。

## 验证

- 本地通过 `go test ./...` 和 Node 前端测试（419 项）。
- 新增回归覆盖公网来源与代理信任、NAT/CGNAT 地址筛选、手工地址保留、地址族与旧版哈希、监听恢复、逐族健康检查、Cloudflare 重复记录与 A/AAAA 切换、自然月请求、请求缓存失效、周期流量和跨回源播放凭据。
- Linux 端口隔离用例在非 Linux 环境会跳过；正式发布工作流还会在 Linux 执行 Go/race、安装升级、静态安全检查与构建校验。
