# v1.11.13

本版本加入节点删除时的 Agent 自卸载，并修正节点路由清理的并发竞态；同时为 WebSocket 握手响应头增加与 Go HTTP Transport 默认值一致的大小限制。

## Agent 自动卸载

- 删除节点时，Controller 先把节点冻结为待删除状态，清理其站点路由和 DNS，确认没有调度引用后才向兼容的 Agent 下发卸载命令。
- 标准 Linux systemd 和 OpenRC 安装的 Agent 会停止服务，使用独立恢复进程删除服务定义、程序、注册凭据和本地状态，再向 Controller 确认完成。Controller 收到经过节点身份、请求编号和 Agent 凭据验证的确认后，才删除节点记录。
- 节点离线或 DNS 清理失败时，删除保持待处理，稍后可重试；不会提前卸载 Agent。强制移除仅清理 Controller 上的节点记录，不会声称已远程卸载。
- 标准安装使用固定的 `/var/lib/meridian-agent/state.json` 状态路径。通过自定义 `--state` 安装的 Agent 不报告自卸载能力，删除面板记录后需按实际安装方式手动卸载。

## 节点路由与地址族

- 删除节点期间会禁止新的手动或自动分配，并在取得每个站点调度锁后重新读取实际分配。若站点已迁往其他节点，不会根据旧快照清理该站点的新路由或 DNS。
- 只有所有站点引用清零后，删除才会进入 Agent 卸载阶段；清理失败保留可恢复的待删除状态。
- DNS 发布策略可以在对应地址尚未上报时保存，DNS 等待所选族地址到达；Agent 监听族仍由发布策略和可用地址决定。
- 移除已废弃的监听网卡绑定链路。旧版客户端发送的 `listen_interface` 字段会被兼容接收并忽略，数据库兼容列保留；IPv4 与 IPv6 监听仍相互隔离。

## WebSocket 握手限制

手动 WebSocket 上游握手现在最多读取 **10 MiB** 响应头，达到限制时返回 502 并关闭上游连接。握手解析和后续隧道共用缓冲读取器，因此仍会保留握手后预读的帧数据。

## 数据库升级与回退

从正式版 v1.11.12（schema 61）升级时，数据库自动迁移至 schema 63；其中包括节点 Agent 卸载状态和待删除状态。升级前备份数据库及 Meridian 管理的 TLS 状态。schema 63 数据库不能直接交给 v1.11.12 或更早版本使用。

回退到 v1.11.12 时，先停止服务，再恢复升级前的 schema 61 数据库和配套 TLS 状态；只替换程序镜像不会降级数据库。Agent 自动卸载功能要求 Controller 和 Agent 使用支持该协议的版本。
