## 项目分析与审查范围

项目以 Go 实现主控与 Agent，共用反向代理核心，以 SQLite 保存管理配置和统计数据，前端为原生 JavaScript。核心复杂度集中在 HTTP/WebSocket 代理、动态播放地址改写、代理实例生命周期，以及主控—Agent—DNS 三方状态协调。

已有安全措施包括管理员初始化令牌、会话版本校验、同源检查、登录限流、管理 Cookie 转发过滤、动态目标 DNS 固定和地址校验、备份加密与归档路径限制。测试覆盖了大量单模块行为。本轮发现的问题主要发生在模块组合和状态切换处，因此“测试通过”仍不足以说明上述流程可靠。

本轮重点阅读认证与路由、代理及故障转移、动态重定向、缓存、节点配置与调度、观看记录采集、备份恢复，并检查前端 API/路由和 CI 配置。采用源码追踪、现有测试和新增隔离用例验证；不是逐行穷尽审计。未访问部署服务器、修改 DNS 或使用生产账号。

## R1 · P1：Agent 缓存跨站点串用

**位置：** [edge_agent.go:493–515](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/edge_agent.go#L493-L515)、[edge_agent.go:544](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/edge_agent.go#L544)、[asset_cache.go:128–143](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/asset_cache.go#L128-L143)。

`buildEdgeProxy` 每次建立新的内存数据库，把中央站点 ID 清零后重新自增分配。本地 ID 因路由增减而变化，但缓存一直保存在同一个 `stateDir/asset-cache`。缓存键使用这个本地 ID、目标 URL、部分请求头及客户端凭据，没有中央站点 ID，也没有运行时自定义上游请求头的版本。

**触发条件：** 开启资源缓存；路由调整后另一站点占用了旧的本地 ID；两站点请求同一个上游资源 URL，客户端缓存键相关字段相同。即使两站点配置了不同的自定义上游身份请求头，缓存仍会碰撞。

**复现结果：** 先让中央站点 100 / `a.example.test` 缓存图片，再将 Agent 配置替换成中央站点 101 / `b.example.test`。上游根据 `X-Origin-Secret` 返回不同内容。第二站实际收到 `a.example.test` 的内容，上游调用总数仍为 1，证明直接命中了旧站缓存。

**修复：** Agent 缓存目录改用控制器站点 ID 加配置摘要作为命名空间，不再使用临时 SQLite ID；旧配置命名空间仍纳入同一站点的总预算。补充了增删前序站点、自定义上游请求头变化的回归测试。

## R2 · P1：在 DNS 切换完成前撤销旧节点路由

**位置：** [site_node_scheduler.go:216–249](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/site_node_scheduler.go#L216-L249)、[site_node_scheduler.go:286–288](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/site_node_scheduler.go#L286-L288)、[site_node_scheduler.go:612–682](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/site_node_scheduler.go#L612-L682)。

`refreshSiteAssignments` 先修改 `desired_node_id`；`buildAgentConfig` 只下发属于 desired 节点的路由。此时 `applied_node_id` 和真实 DNS 可能仍指向旧节点，新节点也可能尚未取得配置、监听失败或未通过健康检查。

**复现结果：** 设置 DNS 已应用到旧节点，同时把期望节点改为新节点；新节点尚未应用配置。旧节点请求配置时立即得到零条路由。该用例没有调用 Cloudflare，验证的是 DNS 提交前的控制状态。

**影响：** 旧 Agent 应用空配置会停止入口。即使新节点或 DNS 更新失败，旧节点也无法继续承担流量；正常切换时，仍使用缓存 DNS 的客户端也可能连到已经撤销路由的旧节点。

**修复：** Agent 配置同时保留 `desired_node_id` 和仍由 `applied_node_id` 指向的旧节点路由；旧入口会继续服务，直到 DNS 协调完成并把 applied 节点更新为新节点。此项与 R3 一起覆盖了切换期间的存量连接。

## R3 · P1：普通配置更新会取消正在播放的请求

**位置：** [edge_agent.go:644–686](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/edge_agent.go#L644-L686)、[edge_agent.go:258–270](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/edge_agent.go#L258-L270)、[proxy_manager.go:205–236](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/proxy_manager.go#L205-L236)。

每次配置 Hash 改变，Agent 都重建整个代理集合，然后执行 `go oldBundle.close()`。该调用最终进入 `ProxyInstance.shutdown`，立即取消实例上下文、设置当前读写截止时间并关闭 WebSocket；并非先允许存量播放自然结束。

**复现结果：** 在旧实例登记一个进行中的请求，只修改站点显示名称，执行 `runtime.apply`。旧请求的实例上下文立刻被取消。该用例验证的是实际取消路径，没有连接真实播放器。

**影响：** 改站点名称、增加其他站点、证书更新等导致配置变化时，现有 HTTP 视频流和 WebSocket 都可能被打断，影响同一 Agent 上未修改的站点。

**修复：** 配置热更新现在使用独立的排空路径：旧实例停止接收新请求，但保留存量请求的上下文，最多等待 15 秒后才强制取消。显式停机仍使用原来的立即关闭路径。

## R4 · P1：自动调度持续选中监听失败节点

**位置：** [node_repository.go:415–466](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/node_repository.go#L415-L466)、[site_node_scheduler.go:634–641](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/site_node_scheduler.go#L634-L641)。

`nodeEligible` 只检查启用、心跳在线及流量未耗尽，不检查已经上报的 `AgentListenerError`。调度器按优先级选中节点后，DNS 协调阶段才发现监听错误并返回；失败结果没有反馈到候选排除逻辑。

**复现结果：** 两台节点均在线。高优先级节点明确上报 `bind: address already in use`，另一台节点没有监听错误；`NodeControlSnapshot` 仍选中故障节点。

**影响：** 一直发送心跳但无法监听的 Agent 会长期占据自动选择结果，即使有可用备用节点也不切换。入口探测失败也缺少候选退避机制。

**修复：** 自动调度会排除带 `AgentListenerError` 的节点；固定模式仍保持明确错误。入口探测失败的 DNS 协调不会覆盖当前记录，配合 R2 的 applied 路由保留策略继续维持旧入口。

## R5 · P2：缓存忽略第二行及后续缓存控制头

**位置：** [asset_cache.go:301–315](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/asset_cache.go#L301-L315)。

缓存准入使用 `Header.Get("Cache-Control")` 与 `Header.Get("Vary")`。Go 的 `Header.Get` 只返回第一个值，不会自动合并所有字段行，见 [Go 官方文档](https://pkg.go.dev/net/http#Header.Get)。

**复现结果：** 以下两种响应都被判定为可缓存：

```http
Content-Type: image/jpeg
Cache-Control: public
Cache-Control: no-store
```

```http
Content-Type: image/jpeg
Vary: Accept-Encoding
Vary: X-User-ID
```

第一种不应写入缓存；第二种不能只按目前缓存键复用。否则会持久保存原本禁止存储的内容，或向不同变体请求返回错误图片/资源。[RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html) 定义了 `no-store` 和 `Vary` 对缓存存储、复用的约束。

**修复：** 使用 `Header.Values` 合并解析所有 Cache-Control / Vary 字段；任一行出现禁止缓存指令、不支持的变体或 `Vary: *` 都拒绝缓存。

## R6 · P2：超限流式请求体被采集器截掉前半段

**位置：** [edge_agent.go:438–446](https://github.com/chanhui800/Meridian/blob/9b347409dec97ee84c509b96a3c27bf4355e3498/edge_agent.go#L438-L446)。

播放状态采集对未知长度请求体预读最多 `8 KiB + 1`。只有读取成功且没有超限时才把内容放回 `r.Body`；超限或读错误时，已经消费的字节不会恢复，接下来却继续调用代理。

**复现结果：** 构造一个未知长度、按 chunked 传输语义处理的 8212 字节 `/Sessions/Playing/Progress` 请求。下游处理器只读到了 19 字节，前 8193 字节被采集器吃掉。

**影响：** 上游可能收到无效 JSON、表单或压缩数据，导致播放进度同步失败。即使选择放弃记录超限遥测，也不能破坏正常代理请求。

**修复：** 采集器用可关闭的重放 reader 把已读取前缀和未读流重新接回请求体；超限只跳过遥测，不截断上游请求。

## 节点调度页面未保存编辑修复

节点页原有 5 秒轮询会直接重绘站点调度行，用户刚勾选的“启用节点调度”、模式或固定节点会被服务端旧快照覆盖。现在前端记录当前页面的未保存草稿，自动刷新只更新状态文本并保留本地编辑值；保存成功后删除对应草稿，离开并重新进入页面则重新读取服务端状态。新增前端回归测试覆盖勾选、模式和固定节点选择在刷新重绘后的保持行为。
