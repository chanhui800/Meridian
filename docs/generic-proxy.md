# 通用反代模式

通用反代在每个 HTTP(S) 请求的路径中解析回源目标。一个 Meridian 站点入口可以连接多台 Emby/Jellyfin 服务器，也可以反代其他 HTTP(S) 服务，无需为每个目标创建固定回源线路。

新增站点默认使用固定回源模式。通用模式需要在添加或编辑站点时主动开启“通用反代”开关。安装方法见 [README](../README.md#快速安装)，节点准备与安装见[节点调度](node-scheduling.md)和 [Agent 安装](agent-installation.md)。

## 创建通用站点

1. 打开“站点管理”，点击“添加站点”，填写站点名称。
2. 在“回源方式”开启“通用反代”。固定回源地址和备用线路无需填写。
3. 在“访问入口”选择域名前缀或独立端口。
4. 按需调整 UA、流量额度、限速，并在“高级策略”开启观看历史。
5. 保存后，将站点入口填写到客户端。

| 入口 | 示例服务器地址 | 配置方式 |
| --- | --- | --- |
| 域名前缀 | `https://gateway.example.com:9090` | 配置站点域名或域名前缀，使用已部署的 HTTPS 入口；可启用节点调度 |
| 独立端口 | `http://panel.example.com:9001` | 给站点分配空闲监听端口，由该主控直接承载 |

通用模式不支持站点的“路径前缀”入口。客户端填写的回源路径是通用路由的一部分，例如 `/emby`；它与 Meridian 的站点路径前缀入口是两个不同的配置。

域名入口需要有效的 TLS 入口或已部署的外部反代。已有外部反代承载 Host 入口时，设置 `PANEL_EXTERNAL_PROXY_ENABLED=true` 并配置实际可信代理来源，详见 [README 的入口与环境变量说明](../README.md#常用环境变量)。

## 客户端的服务器地址与路径

服务器地址填写 Meridian 站点入口，路径填写要连接的完整 HTTP(S) 回源 URL。以下示例适用于支持单独路径栏的媒体客户端：

| 客户端字段 | 填写内容 |
| --- | --- |
| 服务器地址 | `https://gateway.example.com:9090` |
| 路径 | `http://192.168.1.10:8096/emby` |

客户端请求 `Items` 时，形成的请求与实际回源为：

```text
客户端请求
https://gateway.example.com:9090/http://192.168.1.10:8096/emby/Items?Ids=123

实际回源
http://192.168.1.10:8096/emby/Items?Ids=123
```

入口 URL 与回源 URL 分别指定协议和端口。入口使用 HTTPS，不要求回源也使用 HTTPS；入口端口 `9090` 也不会替代回源端口 `8096`。请求的查询参数随请求传递到回源服务。

按媒体服务器的实际 Base URL 填写路径：

| 回源服务 | 客户端路径示例 |
| --- | --- |
| Emby 根路径 | `http://192.168.1.10:8096` |
| Emby 挂载在 `/emby` | `http://192.168.1.10:8096/emby` |
| HTTPS Jellyfin 挂载在 `/jellyfin` | `https://media.example.com:8920/jellyfin` |
| 主控或节点本机服务 | `http://localhost:8096/emby` |
| IPv6 内网服务 | `http://[fd00::10]:8096/emby` |

同一个站点入口可供多个客户端服务器条目使用，每个条目填写不同的回源路径即可。只有完整服务器 URL 输入框的客户端，可以使用下文的完整通用路由 URL；具体是否保留 Base URL 由客户端决定。

## 内置通用路由格式

除了在路径中直接放入完整回源 URL，还支持以下格式：

```text
/_proxy/v1/{http|https}/{主机:端口}/{回源路径}
```

HTTP 示例：

```text
客户端路径
/_proxy/v1/http/192.168.1.10:8096/emby

完整服务器 URL
https://gateway.example.com:9090/_proxy/v1/http/192.168.1.10:8096/emby

请求 Items
https://gateway.example.com:9090/_proxy/v1/http/192.168.1.10:8096/emby/Items?Ids=123
```

HTTPS 与 IPv6 示例：

```text
https://gateway.example.com:9090/_proxy/v1/https/media.example.com:8920/jellyfin/Items
https://gateway.example.com:9090/_proxy/v1/http/[fd00::10]:8096/emby/Items
```

两种格式都支持域名、IPv4 和 IPv6，IPv6 地址需用方括号包裹。端口范围为 `1–65535`；省略端口时使用 HTTP/80 或 HTTPS/443。目标仅支持 HTTP 和 HTTPS，不接受带 `用户名:密码@` 的目标地址，也不提供 CONNECT 隧道。媒体服务器登录信息使用客户端正常的认证流程填写。

## 播放地址与媒体后端

通用模式会处理 PlaybackInfo、HLS/DASH 清单和 HTTP 重定向中的 HTTP(S) 地址，把它们改写成 `/_proxy/v1/...` 路由。媒体、字幕、音轨、分片以及不同服务器上的资源可以继续通过同一 Meridian 入口访问。相对地址按上游响应所在位置解析，支持本机和内网资源目标。

例如，Emby 的 API 与媒体文件由两个服务提供：

```text
1. 客户端请求 PlaybackInfo
   /http://api.example.com:8096/emby/Items/123/PlaybackInfo

2. 返回的播放地址改写为
   /_proxy/v1/http/api.example.com:8096/videos/123/original.mkv

3. API 服务将媒体请求重定向到
   http://192.168.1.20:9000/media/movie.mkv

4. 重定向地址改写为
   /_proxy/v1/http/192.168.1.20:9000/media/movie.mkv
```

客户端继续经 Meridian 访问重定向后的媒体后端。主视频流在通用模式下使用反代，Range、HEAD、查询参数与实际收发字节继续按请求处理。请求日志分别显示 API 服务的重定向与媒体后端的响应，最终后端地址来自实际回源。

部分媒体客户端会把已改写的路由追加到配置的 Emby 基路径，例如 `/http://api.example.com:8096/emby/_proxy/v1/http/192.168.1.20:9000/media/movie.mkv`。Meridian 会识别其中的通用路由并访问它声明的媒体目标。Emby 挂载在 `/emby` 时，PlaybackInfo 中依赖该挂载的自定义播放路径也会保留相应基路径。

普通 API、图片、字幕和 WebSocket 请求也可使用通用路由反代。通用模式不对任意 HTML 页面执行整页地址改写。

## 观看历史与来源显示

观看历史可在通用站点的“高级策略”中开启。开启后记录后续成功的播放状态，停止意图与源站停止确认保持独立；只有满足原有成功会话与源站确认条件时才确认停止。

同一个通用站点访问多个媒体服务器时，媒体 ID、播放会话、剧集归属和元数据按“协议、主机、有效端口、API 挂载路径”隔离。不同来源返回相同媒体 ID 或会话 ID 时，仍各自记录；同一服务器的 `/alpha/emby` 和 `/beta/emby` 也分别归属。

观看历史卡片、正在观看卡片和详情显示服务器地址，例如：

```text
http://192.168.1.10:8096
https://media.example.com:8920
https://media.example.com:443
```

页面地址仅包含协议、主机与端口，不包含 `/emby` 等挂载路径、查询参数或登录凭据。两条记录可以显示同一个服务器地址而属于不同 API 挂载。固定回源记录不显示服务器地址栏。

升级时，已有通用记录只有在保留的成功 API 日志能精确对应其来源时才补齐地址；无法确认的记录会在该来源后续播放时更新。同一来源的新播放可补齐其已有记录。观看历史保留期继续使用“全局设置 → 媒体资料”的配置，通用模式不提供固定站点的保号周期。

## 节点调度与本机、内网目标

域名前缀入口可以在“节点调度”中选择跟随全局节点或固定到指定节点。通用站点需要 v1.11.9 或更新版本的 Agent；旧 Agent 会显示等待升级，不会把通用配置作为固定回源运行。已经由旧节点承载的固定站点，需要先升级生效节点的 Agent，再将站点切换为通用模式。

回源目标不要求公网地址。连接由实际承载站点的运行环境发起：

| 承载位置 | `localhost` 的含义 | 内网目标的访问条件 |
| --- | --- | --- |
| 未启用调度的 Controller | Controller 进程所在主机或容器的本机 | Controller 能连接该目标 |
| 生效的 Edge Agent | 该节点的本机 | 生效节点能连接该目标 |

固定节点适合只在某个节点可达的服务。跟随全局调度时，可能被选中的节点都需要能够访问目标；DNS 切换不会改变目标 URL 的含义。Docker 的 `localhost` 指向容器运行环境，使用主机网络模式时与宿主机网络一致。

Agent 应用配置并通过 HTTPS/SNI 健康检查后，Controller 才更新自己管理的站点 DNS。首次正式接管前主控继续提供服务；接管后的行为如下：

- 主控对该站点的新请求返回 HTTP 421，避免旧 DNS 缓存继续让主控回源。
- 已开始的视频与 WebSocket 连接继续运行，DNS 切换只影响新连接。
- 节点切换等待或失败时，主控入口保持关闭。
- 关闭调度后，需完成 DNS 与节点清理，主控才重新接受该站点的新请求。

这些规则同时适用于固定回源和通用反代站点。完整步骤见[节点调度](node-scheduling.md)。

## 能力范围与模式切换

| 能力 | 通用反代模式 |
| --- | --- |
| HTTP(S) API、资源、Range/HEAD、WebSocket 反代 | 支持 |
| PlaybackInfo、HLS/DASH、HTTP 重定向中的地址改写 | 支持 |
| 请求日志、后端地址、流量额度、限速、UA 策略 | 支持 |
| 观看历史与多来源隔离 | 可选开启 |
| 域名入口的全局或固定节点调度 | 需要兼容 Agent |
| 固定主线路、备用线路与自动回切 | 不启用 |
| 主视频流直连选项、预设播放地址 | 不启用，媒体继续反代 |
| 静态资源缓存、保号周期、站点固定请求头 | 不启用 |
| 站点路径前缀入口、CONNECT 隧道 | 不支持 |

保存固定站点为通用模式时，会清除固定回源线路、预设播放地址、缓存、保号周期和站点固定请求头设置。切回固定模式时需重新填写这些设置。观看历史开关保持独立，普通编辑不会自动关闭已有观看历史。

## 常见问题

**站点入口返回“请求路径无效”。** 通用站点根路径没有固定回源目标。使用完整回源 URL 路径或 `/_proxy/v1/...` 路由测试，并确认客户端请求仍包含所配置的路径。

**客户端能登录但不能播放。** 查看请求日志中 PlaybackInfo、重定向和媒体请求的后端地址，确认实际承载站点的主控或节点能访问媒体目标，并检查客户端是否保留改写后的路由。API 可达并不代表另一个媒体后端也可达。

**使用 `localhost` 或内网地址连接失败。** 从当前承载站点的主控或生效节点检查网络和目标监听端口。节点调度改变后，`localhost` 访问的是新节点。

**节点调度显示等待升级。** 等待已注册 Agent 完成与 Controller 匹配版本的自动更新，并确认节点报告“配置已应用”；普通升级无需重新注册。

**主控请求返回 421。** 站点已由节点正式接管。检查客户端的 DNS 与连接缓存，让新请求访问生效节点；如果要恢复主控承载，关闭调度并等待清理完成。

**旧观看记录没有服务器地址。** 保留日志不足以精确确认来源时不会猜测地址，该来源后续成功播放会补齐对应记录。
